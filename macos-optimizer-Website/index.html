macos-optimizer: The Control Panel

I keep a menu driven macOS script in script.sh. On start it prints system information, hostname, macOS version, kernel, CPU, memory, and storage, then it loops a numbered menu. Twenty five switches sit on one board. I built this page as that board.

License: GPL-3.0, held in the LICENSE file in the repo. Script: script.sh, 383 lines at the head this page was built from. Upstream: adapted from Sami Halawa, github.com/samihalawa/macos-optimizer.

The board

I grouped the rows by what they touch. Each row gives the menu number, the label I use for it, and the command or function the script runs for that number. Read the yellow box before you touch a switch.

The switch board

Illustration only: flipping a switch on this page changes nothing on any machine. These switches illustrate the menu in script.sh. They are not a live control, they send nothing, and they run nothing.

The one switch I flipped the other way

Upstream, then mine

I did not write this script from a blank file. It is adapted from Sami Halawa's macOS optimizer, and the copyright at the top of script.sh still names Sami Halawa. My changes sit on top of that base, and I list them as a delta, not as the whole work.

The headline change is Gatekeeper. The original disabled Gatekeeper with sudo spctl --master-disable. I removed that line. In my version, option 23 runs sudo spctl --master-enable. I do not count turning off the check that stops unsigned software as an optimisation, so I wired the same slot in the opposite direction. That is why switch 23 sits flipped on the board above, in magenta, against the rest.

Full upstream credit: Sami Halawa, github.com/samihalawa/macos-optimizer. If you reuse the script, follow the LICENSE file in the repo and keep that credit.

My delta, in full

  • Gatekeeper: option 23 enables Gatekeeper instead of disabling it. See the capture below, lines 169 to 181.
  • The find. fix: option 18 and the matching step in run_all appended find. -name '.DS_Store' to ~/.profile. find. is not a command, so that line could never work. Both places now append find . -name '.DS_Store', with a space before the dot.
  • The option 24 label: the menu now lists 1, 3, 4, 5, 7, 11, 12, 16, which is the set run_safe actually runs. An earlier label listed TRIM, and run_safe has never run TRIM.
  • MAGENTA: the intro line that prints the project address used a MAGENTA colour variable that was never defined, so the address printed without colour. I defined MAGENTA at line 15, alongside the other colours.

Option 24, the master row

Option 24 is the panel master row. It calls run_safe, and run_safe runs exactly eight actions: 1, 3, 4, 5, 7, 11, 12, 16. On the board above I showed those eight as sub-switches under row 24, because that is how the function is wired. TRIM stays out on purpose: trimforce asks its own confirmation and expects a restart, so I cannot fold it into a set that runs from a single menu choice.

Capture: run_safe, script.sh lines 127 to 153

function run_safe() {
    # I keep this set to exactly the eight actions below, and I keep
    # the menu label for option 24 in step with it, because a previous
    # label listed TRIM and this function has never run TRIM. I leave
    # TRIM out on purpose: trimforce asks its own confirmation and
    # expects a restart, so I cannot fold it into a set that runs
    # from a single menu choice.
    echo "Running safe optimizations..."
    loading
    sudo mdutil -a -i off
    check_status "Spotlight indexing disabled"
    defaults write NSGlobalDomain NSAppSleepDisabled -bool YES
    check_status "App Nap disabled"
    defaults write NSGlobalDomain NSDisableAutomaticTermination -bool YES
    check_status "Automatic termination of inactive apps disabled"
    sudo fsck -fy
    check_status "Continuous disk checking enabled"
    sudo pmset -a lidwake 1
    check_status "Lid wake enabled"
    sudo dscacheutil -flushcache
    check_status "DNS cache flushed"
    sudo mdutil -E /
    check_status "Spotlight optimized for faster searches"
    defaults write com.apple.finder EmptyTrashSecurely -bool true
    check_status "Secure Empty Trash enabled"
    echo -e "${GREEN}Safe optimizations complete!${NC}"
}

The sheets

I drew the repo as notebook sheets. VISUAL.md in the Visuals folder describes five sheets: architecture, flowchart, product map, data flow, and statistics. The folder itself holds six PNG sheets, because schematic.png sits there as a sixth sheet that VISUAL.md does not list. I show all six below and I note the count difference here, rather than quietly dropping the extra sheet.

The sheets follow a paper rule from VISUAL.md: drawn on notebook paper with three binder holes down the left side, nothing drawn over a hole, and a machine check that counted 0 ink pixels in the hole zones for that set. The PDF in the same folder, macos-optimizer-Visuals.pdf, holds the five sheets VISUAL.md lists, in its order, for printing.

Honest limits, stated plainly

The intro in script.sh says no changes will be made without your explicit confirmation. That is not how the menu behaves. Choosing a menu item applies that change immediately. Only TRIM, option 6, asks for confirmation first. I left the intro wording as written and I record the mismatch here and in the README, rather than rebuilding confirmations for all 25 options.

This script is macOS only. It calls sw_vers, sysctl, pmset, mdutil, and other macOS tools, so it does not run as written on Linux or Windows.

I verified the script with bash -n only. I did not run it live, and this page stages no run. Running it would change a real Mac's settings, which is exactly why a syntax check is the honest check here.

No switch on this page controls anything. If you want the real switches, run script.sh on a Mac you own, read each row before you pick it, and keep a backup first, as the script intro itself advises.
